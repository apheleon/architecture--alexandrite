# Задание 4. Логирование

## Логи
### Уровень INFO
1. Статус заказа клиента поменялся. Сохраняем guid пользователя, order-ID, timestamp, system
2. Заказ отправили в MES, пишем: order-ID, timestamp, MES internal order stage (начало расчёта, окончание расчета)

Нам также понадобятся уровни WARN, ERROR, DEBUG. 
**WARN** - будем использовать если в процессе работы интересующие нас параметры выходят за границы, например: стоимость заказа очень высока(необходимо ручное вмешательство), в очереди много заказов
**ERROR** - у нас непредвиденная ошибка: MES 500, RabbitMQ не отвечает, кончилось место, денение на 0 и тд...
**DEBUG** - информация о контексте крайних случаев, например: исследуем деление на 0 и обнаруживаем ошибку в формуле или входных параметрах.


## Мотивация
В первую очередь логироваение и трейсинг нужно настроить на MES, так как клиенты испытывают трудности с исполнением заказов. Заказы теряются, их не исполняют в срок. Нужно быть уверенным, что MES всё отрабатывает правильно и в полном объёме. Это самая значительная часть бизнеса.

1. Логи помогут понять проходит заказ полный цикл внутри MES или нет.
2. В процессе работы могут быть выявлены крайние случаи, которые API MES отрабатывает не корректно.
3. Бизнес сможет настроить системы приоритизации выполнения заказа, например: слишком сложная в расчёте модель оказалась самой дешёвой.

## Предлагаемое решение
Политика безопасности
1. VPN + 2FA + RBAC
2. Чувствительные данные маскируем(имена, контактные данные)
3. Логи шифруем при передаче TLS, при хранении AES-256
4. Логи можно разделить по классификатору данных, сегрегировать: то что особенно ценно - хранить отдельно с более высоким уровнем доступа

Хранение
1. Один секвис - один индекс
2. Для чувствительной информации - отдельный индекс
3. Хранилище elastic, s3 для архива

По времени
1. То что связано с исполнением обязательств перед клиентом - до истечения сроков установленных в договоре, например срока гарантии
2. Системные - 90 дней
3. Чувствительные - 10 дней

Ротация - ежедневная, резервное копирование - ежедневное

Размер - можно поставить в 10gb с алертом при привышении уровня в 80%, так мы сможем подстроить ротацию. Например скидывать в новый файл при превышении какого-то порога.
